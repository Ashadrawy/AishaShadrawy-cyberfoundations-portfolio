# Start Here

If this is your first time using GitHub, welcome — you're in the right place, and you don't need to know anything yet. This page is your first lab, and it doubles as your first real commit.

## What Just Happened?

If you got to this repo by clicking **Use this template** on `cyberfoundations-student-portfolio-template`, you now have your own independent copy of this structure. It is yours. Nothing you do here affects the original template, and nothing anyone else does affects you.

If you haven't done that yet, stop here and go back to your Week 1 lesson in Circle for the exact steps — you'll want your own copy before continuing.

## Your First Commit

This takes about 10 minutes and puts your name on the internet as someone building real technical skills.

### Step 1 — Open Your Main README

1. Open **your own portfolio repository** on GitHub. Check that your username appears before the repository name.
2. Click the **Code** tab to return to the main file list. This top-level location is called the repository **root**.
3. Click [`README.md`](../README.md) in that main file list, then click the **pencil icon (Edit)** above the file.

Your introduction belongs in this root `README.md`. The file `week-01/README-week01-root.md` is the Week 1 overview, not your personal introduction. There is no `week-01/README.md` in this template.

### Step 2 — Add Your Introduction in About Me

Find `## About Me` near the top, directly below the main title and the **New here?** sentence. Replace only the bracketed instruction paragraph under `## About Me` with at least three sentences:

- Who are you?
- Why are you learning cybersecurity?
- What is one learning goal for this course?

Keep the `## About Me` heading, main title, **New here?** link, and all other README content. If your copy does not have an **About Me** section yet, add it in that same location, above the paragraph beginning **This repository documents**.

Here is an example of the section after editing. Write your own introduction instead of submitting the example:

```markdown
## About Me

My name is Jordan, and I am beginning my cybersecurity learning journey with CyberVisionaries Institute. I am interested in cybersecurity because I want to understand how people, systems, and data are protected. My goal in this course is to build hands-on skills and learn to document my work clearly.
```

### Step 3 — Preview and Save Your Change

1. Click **Preview** above the editor. Confirm your introduction appears under **About Me** and the rest of the README is still there.
2. Click **Commit changes…** to open the save dialog.
3. Enter `Week 1: Add intro to README` as the commit message.
4. In your own portfolio, select **Commit directly to the main branch** if that option is available. If your repository does not allow this, ask your instructor for help.
5. Click **Commit changes** in the dialog to finish saving.

### Step 4 — Verify Your Introduction

Return to the repository's **Code** tab and reopen the main `README.md`. Your own three-sentence introduction should appear under **About Me**, without the bracketed instruction paragraph. Refresh the page to confirm it was saved.

### Optional: Try the Lab Portal Practice Worksheet

The Week 1 Practice Worksheet is a separate, ungraded test of the portal's submission flow. **Submit to GitHub** saves it to `week-01/practice-worksheet.md`. It does not add an introduction to your main README and does not replace the steps above.

## What Does "Commit" Actually Mean?

A commit is like hitting Save — except GitHub keeps a record of every save you ever make, with a timestamp and a message describing what changed. You can always go back and see exactly what changed and when. Every commit you make in this course adds to your professional history.

## Where Things Go From Here

`week-01/` and `week-02/` are already built into this repo — nothing to create yet. Every week follows the same rhythm:

1. Read that week's `README-week0X-root.md` for the overview and checklist
2. Complete the lab in the Lab Portal — it submits your work straight into `week-0X/labs/`
3. Add more detail there yourself if you want to
4. Summarize the concepts in `week-0X/notes.md`
5. Reflect in `week-0X/reflection.md`
6. Commit — see that week's `labs/README-week0X-submissions.md` for exact commit steps

From Week 3 on, you create the next `week-0X/` folder yourself, matching this same structure.
